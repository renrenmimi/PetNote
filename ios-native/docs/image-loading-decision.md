**状态** 已决策，待阶段 5/7 的真机实测复核（下面写明了推翻它的具体条件）。

## 我们实际需要的能力，以及每种方案怎么满足

**一个前提改变了这道题**：PetNote 的媒体走 Cloudinary，而**尺寸变换在服务端**
（`src/utils/cloudinaryUrl.ts` 的 `optimizeCloudinaryUrl` 在 URL 里插
`w_800,q_auto,f_auto`）`[代码]`。所以"按显示尺寸解码"这件通常最难的事，
主要变成了"请求正确尺寸的 URL"，本地降采样只在少数路径上需要
（非 Cloudinary 的 URL、以及视频封面帧）。

| 能力 | 成熟依赖 | 自建用什么 |
| --- | --- | --- |
| 按显示尺寸取图 | 需要自己拼 Cloudinary 变换，库不认识我们的 CDN | 同样自己拼——这部分**没有差别** |
| 本地降采样 | 内置 | `ImageIO` 的 `kCGImageSourceThumbnailMaxPixelSize` |
| 内存缓存 | 内置 | `NSCache`（本身就响应内存压力） |
| 磁盘缓存 | 内置，各家策略不同 | `URLCache`（HTTP 语义，Cloudinary 有 `Cache-Control`） |
| 请求取消 | 内置 | `URLSession` task + `.task(id:)` 生命周期 |
| 同 URL 并发去重 | 内置 | 一个 actor 里的 in-flight 表 |
| 列表预取 | 内置 | `UICollectionViewDataSourcePrefetching` 触发同一个 loader |
| 内存警告清理 | 内置 | `NSCache` + 显式监听 |

## 五项比较

**可靠性**：Nuke 与 Kingfisher 在上面每一项上都是被大量项目验证过的，比第一版自建
代码可靠——这一点不必争。但我们需要的路径窄，而窄路径上的正确性是可测的
（解码尺寸、缓存命中、取消是否真的停止了请求），不依赖"被很多人用过"。

**实际用量**：Kingfisher 的表面积最大（处理器链、GIF、指示器、`KFImage` 修饰符体系），
我们第一阶段用不到其中大部分。Nuke 的表面积适中。用不到的表面积不是零成本：
它们进二进制、进启动路径，也让"某个行为为什么发生"多了一层要读的代码。

**维护成本**：三者都在活跃维护（SDWebImageSwiftUI 最近一次提交在 7 个月前，明显更慢）。
真正的成本项是**与 Swift 6 完全严格并发的兼容性**——工程规格 §1.3 明确不许用
`@unchecked Sendable` 糊过去，所以任何库类型跨越隔离边界时都要逐个确认，
而这件事的工作量在引入之前无法从 README 判断 `[待验证]`。

**可替换性**：无论选哪边，`Core/Media` 都是唯一接触实现的地方。选自建，
将来换 Nuke 只需改这一层；选依赖，同样。**这一项两边等价**，所以它不构成理由。

**自建的真实成本**：约 200–300 行（loader actor + 缓存 + ImageIO 降采样 + 预取入口），
需要自己处理：解码放后台而赋值在主线程、同 URL 去重、取消、内存警告、
把 Cloudinary URL 里的版本号纳入缓存键 `[代码]`。
**不需要**处理的（因为第一阶段范围不含发帖）：HEIC、EXIF 方向、GIF 动画、上传。

## 为什么第一阶段选自建

1. **难的部分已经在服务端。** 尺寸变换由 Cloudinary 做，客户端的图片管线因此比
   通常情况薄很多，而"薄"正是自建划算的条件。
2. **性能归因要干净。** 阶段 7 要回答的是"原生列表在 200 条真实数据下的表现"。
   如果图片管线是第三方的，滚动不达标时第一件事会变成分辨"是我们的问题还是库的"。
   第一阶段的目的就是建立基线，归因清晰比省 200 行更重要。
3. **严格并发下自己的代码可控。** 这是唯一一项自建明确占优、且成本发生在现在的。

**不是**因为"少一个依赖更干净"——那不是理由。Nuke 在能力上确实更完整。

## 什么条件下改变这个结论

**任一条成立就换 Nuke**（首选它而不是 Kingfisher：表面积更接近我们的用量，
现代并发支持更积极）：

- 阶段 7 的滚动实测未达预算（掉帧率 <1%、单帧 <33ms），且 Instruments 指向
  图片解码或缓存为瓶颈；
- 自建实现超过约 400 行，或出现"为了一个常规交互不得不引入复杂抽象"的信号
  （工程规格 §6.4 要求上报的那类信号）；
- 需要渐进解码、动图、或多级缩略图金字塔——这些是库明显更强的地方。

换的时候只改 `Core/Media`，视图层不动。这就是为什么现在选哪边都不是单行道。
