# 上架 App Store 前的检查清单（2026-09-28）

这张表只写已经核对过的事实。凡是需要你决定或开通的，都标“要你”。苹果审核条款的编号来自 App Store Review Guidelines。

## 已经具备

| 项目 | 现状 |
| --- | --- |
| App 图标 | 1024×1024 单张源图，和旧版 Capacitor 的图标是同一个文件（md5 `91a40ffb…`），包里生成的 120×120 图标逐像素一致 |
| 启动画面 | 用原品牌爪印，跟随浅色和深色；冷启动没有黑白闪屏 |
| 在 App 内注销账号（条款 5.1.1(v)） | 设置 → 注销账号：先重新验证身份，再输入 `DELETE`；中途中断可以继续完成 |
| 用户内容的管理（条款 1.2） | 举报帖子、屏蔽用户、联系我们都有 |
| 隐私政策链接 | 登录、注册、设置页都能打开 `petnote.vercel.app/privacy` 和 `/terms`。原文还没有覆盖 iOS 版，见下面“要你”的第 5 项 |
| 权限 | App 不用相机、定位、通讯录、麦克风。选照片用系统的照片选择器，不需要权限 |

## 这次补上的（`ios-native/app-store-prep`）

- **“存储图像”原来不能用。**分享一条帖子的卡片时，系统面板里没有“存储图像”，因为 App 没写“要往相册里加图”的说明，iOS 就不提供这一项。现在补上了说明文字，中英文都有。测试确认：面板里出现“Save Image”；第一次点时系统询问“允许 PetNote 向你的图库添加照片和视频吗？”；允许以后面板关闭，App 一直在前台。App 不读取相册。
- **隐私清单**（`App/PrivacyInfo.xcprivacy`，上架必需）。
  - 申报的数据：邮箱、名字、用户 ID、照片和视频、用户发的内容、联系我们的客服内容。全部和账号关联，只用于 App 的功能，不用于跟踪。
  - 申报的系统接口：只有存 App 自己设置用的 UserDefaults。
  - 链接的 SDK 自带各自的清单，是 Firebase 的登录、数据库、云函数，以及 Google 登录。App 里没有统计分析、崩溃上报或推送的 SDK。
- **加密出口声明**：App 只用标准 HTTPS，属于豁免范围，已经在配置里写明，以后每次上传不用再回答这个问题。

## 要你决定或开通的

1. **付费的 Apple 开发者账号**（每年 99 美元）。现在的免费账号只能装到你自己的手机上，签名 7 天到期，不能上 TestFlight 或 App Store。
2. **正式的 Bundle ID。**现在用的 `dev.local.petnote.native` 只适合本地开发。上架需要一个挂在你付费账号下的正式 ID，比如 `com.你的名字.petnote`，一旦定了以后就不能改。
3. **“通过 Apple 登录”（条款 4.8）。**App 提供 Google 登录，苹果要求同时提供一个同等注重隐私的登录方式，一般就是“通过 Apple 登录”。它需要付费账号开通这项能力，还要在生产环境的 Firebase 里打开 Apple 登录。代码我可以写，开通要你来做。
4. **给苹果审核用的演示账号（条款 2.1）。**App 要登录才能使用，审核员需要一个能登录的账号。要在生产环境建一个专用账号，这属于往生产写数据，要你批准。
5. **隐私政策和服务条款覆盖 iOS 版。**网页上的原文还没有写 iOS 版的情况，逐条对照在 `legal-pages-ios-review.md`，还有 9 个问题等你回答。App Store Connect 里的“隐私营养标签”也要和上面那份隐私清单说的一样。
6. **App Store 页面的材料**：名字、副标题、描述、关键词、支持网址、截图（6.9 英寸和 6.5 英寸 iPhone）、年龄分级问卷。有用户发的内容，分级问卷要如实回答。
7. **连生产环境完整测一遍。**到目前为止所有测试都连测试后端。上架前要用正式版连生产走一遍主要流程；其中发帖、注册会往生产写数据，要你批准。main 上的后端函数源码比线上新一点（媒体账号改成按项目选），要先在测试项目验证过再部署。
